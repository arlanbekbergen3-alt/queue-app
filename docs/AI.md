# ИИ-помощник (необязательно)

Две функции, обе выключены по умолчанию (`AI_ENABLED=false`) и обе только помогают человеку:

1. **Черновик банка вопросов и критериев** (`/protocol`): преподаватель вставляет текст работы, модель предлагает 10-15 вопросов и 3-6 критериев. Это черновик: ничего не попадает в банк, пока преподаватель не проверит, не поправит и не утвердит.
2. **Тренировка студента** (`/practice`): студент отвечает на вопрос из банка, модель говорит, верно ли и что повторить. Это не оценка, результат нигде не сохраняется.

Модель **никогда не оценивает** студентов и не пишет в оценки.

Если функция выключена или Ollama недоступна, остальное приложение работает как раньше: кнопки показывают понятное сообщение, а тренировка предлагает самопроверку по критериям без модели.

## Что уходит наружу

- Черновик: только вставленный текст работы (до `AI_MAX_SOURCE_CHARS` символов). Без имён, талонов, оценок и идентификаторов (проверено тестом `test_only_the_source_text_is_sent_to_the_model`).
- Тренировка: текст выбранного вопроса и ответ студента. Ответ не пишется в БД и в журнал, хранится в памяти процесса только пока задача идёт, результат живёт `AI_PRACTICE_JOB_TTL_SECONDS` (600 с).
- Пока вы используете Ollama на своей машине, данные никуда за её пределы не уходят. Облачный провайдер отправит эти тексты стороннему сервису: подумайте о приватности.

## Установка Ollama и модели

1. Установите Ollama с официального сайта (Windows, macOS, Linux).
2. Скачайте модель: `ollama pull qwen3.5:9b`. Тег `qwen3.5:9b` существует (проверено: модель скачана и работает, см. замер ниже); если её у вас нет, укажите другую в `AI_MODEL` (например, любую поддерживающую русский и JSON-схему).
3. Проверьте: `ollama run qwen3.5:9b "Скажи привет"`. Сервер Ollama слушает порт 11434.
4. Включите функцию в `.env`: `AI_ENABLED=true`. Если приложение работает в Docker, адрес по умолчанию `http://host.docker.internal:11434` указывает на Ollama на хосте (в `docker-compose.yml` для Linux добавлен `host-gateway`). На Docker Desktop для Windows контейнер достал до Ollama, слушающей только `127.0.0.1` (проверено). На Linux, вероятно, нужен `OLLAMA_HOST=0.0.0.0` (**не проверено**).
5. Перезапустите: `docker compose up -d`.

## Настройки (`.env`, значения по умолчанию)

| Переменная | Значение | Что делает |
|---|---|---|
| `AI_ENABLED` | `false` | включает функции |
| `OLLAMA_URL` | `http://host.docker.internal:11434` | адрес сервера моделей |
| `AI_MODEL` | `qwen3.5:9b` | имя модели |
| `AI_TIMEOUT_SECONDS` | `300` | сколько ждать ответ модели |
| `AI_MAX_SOURCE_CHARS` | `12000` | предел текста работы |
| `AI_MAX_RESPONSE_CHARS` | `20000` | предел размера ответа модели |
| `AI_MAX_OUTPUT_TOKENS` | `3000` | предел длины генерации |
| `AI_MIN_QUESTIONS` | `8` | рекомендуемый минимум вопросов в черновике (1-40) |
| `AI_DRAFTS_PER_TEACHER_PER_HOUR` | `5` | лимит черновиков на преподавателя в час |
| `AI_PRACTICE_PER_IP_PER_HOUR` | `30` | лимит проверок тренировки на IP в час |
| `AI_PRACTICE_PER_SESSION_PER_HOUR` | `300` | лимит на код сессии в час |
| `AI_PRACTICE_ANSWER_MAX_CHARS` | `1500` | предел длины ответа студента |
| `AI_PRACTICE_QUEUE_MAX` | `10` | сколько проверок тренировки может ждать |
| `AI_PRACTICE_JOB_TTL_SECONDS` | `600` | сколько хранится результат проверки |

Значения лимитов и размеров выбраны без измерений (допущения).

## Минимум вопросов в черновике

Если после проверки в черновике меньше `AI_MIN_QUESTIONS` (по умолчанию 8) вопросов, задача один раз автоматически повторяет запрос с напоминанием о количестве (поле `reminder` в сообщении пользователя). Из двух ответов берётся тот, где вопросов больше; если повтор не удался (недоступна модель, таймаут, мусор), остаётся первый ответ. Если и после этого вопросов меньше минимума, черновик всё равно показывается, в результате задачи `below_recommended: true`, а страница выводит пометку «Меньше рекомендуемого». Если полезных вопросов нет совсем, задача заканчивается ошибкой `ai_bad_response`. Повтор удлиняет генерацию (до двух обращений к модели), на нагруженном ноутбуке это минуты; лимит `AI_DRAFTS_PER_TEACHER_PER_HOUR` считает задачи, а не обращения. Проверено автотестами с подменой провайдера; на настоящей модели повтор **не запускался**.

## Скорость на процессоре

Измерения выше. Автоматические тесты идут с подменой провайдера. Ожидание для других машин: 9-миллиардная модель на процессоре без GPU отвечает медленно (порядок десятков секунд или минут на черновик, это предположение). Поэтому генерация фоновая: страница опрашивает состояние (в очереди, идёт, готово, ошибка), а сервер не держит запрос и соединение с БД. Одновременно идёт одна генерация на процесс. Реальные цифры запишите после первого запуска.

Модель не запускается на VPS с 1 ГБ памяти: нужен более сильный сервер или облачный API.

## Как заменить провайдера

Провайдер реализует один метод (`services/ai.py`):

```python
class AIProvider(Protocol):
    async def generate_json(
        self, *, system: str, user: str, schema: dict, max_tokens: int
    ) -> dict: ...
```

Он должен вернуть разобранный JSON-объект или бросить `AIUnavailableError`, `AITimeoutError`, `AIBadResponseError`. Чтобы подключить облачный API: напишите класс с этим методом (ключ добавьте в `.env`, значения не коммитьте), замените `_default_provider` на выбор по настройке (например `AI_PROVIDER=ollama|cloud`) и добавьте тесты по образцу `tests/test_ai_drafts.py` (в них провайдер подменяется через `services.ai.provider_factory`). Этого переключателя в коде пока нет.

## Ограничения

- **Модель может ошибаться:** придумывать вопросы вне темы, дублировать, давать слабые критерии. Всегда проверяйте черновик.
- В тренировке модель может сказать студенту неверное. Защита от prompt injection ограничивает, что вывод может сделать (только текст подсказки в окне студента), но не гарантирует правдивость. Описано в `docs/LEARNING.md`, D18.
- Тренировка показывает студентам вопросы банка: включайте её, только если банк не используется на настоящей сдаче.
- Задачи генерации живут в памяти процесса: перезапуск сервера их обрывает (помечаются `ai_interrupted`).
- Замер сделан на одной теме и одной машине (см. выше); другие темы и тихая машина не проверялись. Необязательный интеграционный тест (с хоста нужен `OLLAMA_URL=http://localhost:11434`; прошёл 12.11.2026, 223 с): `RUN_OLLAMA_TESTS=1 OLLAMA_URL=http://localhost:11434 AI_TIMEOUT_SECONDS=600 pytest tests/test_ai_drafts.py -k real_ollama` (по умолчанию пропускается).
