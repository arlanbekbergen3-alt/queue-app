# Передача проекта

Для разработчика, который будет вести проект один и без ИИ-инструментов. Здесь собрано то, что нужно, чтобы запустить, проверить, изменить и выложить проект. Решения и их обоснования лежат в [DECISIONS.md](DECISIONS.md), честные ограничения в [KNOWN_ISSUES.md](KNOWN_ISSUES.md), выкладка на сервер в [DEPLOY.md](DEPLOY.md), набор для пилота в [PILOT.md](PILOT.md).

## 1. Что это

Электронная очередь на сдачу работ плюс протокол сдачи. Студенты входят по коду или QR, преподаватель вызывает, оценивает и видит прогноз, история студентов и аналитика строятся автоматически. Стек: FastAPI (async), SQLAlchemy 2.0, PostgreSQL 15, Alembic, статические страницы без сборки (HTML и JavaScript в `static/`), pytest, Playwright, k6, Docker. Процесс приложения один (SSE, лимиты, метрики и счётчики перебора кода живут в памяти).

## 2. Запуск и остановка

### Локально в Docker

```bash
cp .env.example .env          # заполнить DB_PASSWORD, JWT_SECRET_KEY (от 32 символов), TEACHER_INVITE_CODE (от 8)
docker compose up -d --build  # postgres (queue_db) и web (queue_api); миграции применяются при старте web
docker compose ps             # оба healthy
curl -s http://127.0.0.1:8000/ready
docker compose logs -f web    # журнал
docker compose stop           # остановить, данные сохраняются в томе
docker compose down           # убрать контейнеры (том остаётся); `down -v` стирает и данные
```

Страницы: `/` студент, `/teacher` преподаватель, `/protocol` работы и журнал, `/students`, `/spaces`, `/practice`, Swagger на `/docs`.

### Без Docker

Поднять PostgreSQL 15, в `.env` указать `DATABASE_URL=postgresql+asyncpg://postgres:ПАРОЛЬ@localhost:5434/queue_db`, затем:

```bash
python3.11 -m venv .venv && . .venv/bin/activate      # на Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
alembic upgrade head
uvicorn main:app --port 8000      # один процесс, без --workers
```

### На сервере

Пошагово в [DEPLOY.md](DEPLOY.md): `docker-compose.prod.yml`, `.env` по образцу `.env.prod.example`, Caddy с HTTPS, резервные копии `deploy/backup.sh`. Запуск `docker compose -f docker-compose.prod.yml up -d --build`, остановка `docker compose -f docker-compose.prod.yml stop`.

## 3. Тесты, линтеры, e2e, нагрузка

Нужны Python 3.11, PostgreSQL (тесты сами создают базы `queue_test`, `queue_migration_test`, `queue_e2e` рядом с основной, переменная `DATABASE_URL` перекрывает `.env`) и один раз `playwright install chromium`.

```bash
ruff check . && ruff format --check .      # стиль (длина строки 100)
mypy                                        # типы, настройки в pyproject.toml
alembic upgrade head && alembic check       # модели совпадают с миграциями
pytest --cov                                # юнит и интеграционные, 500+ тестов, 8-16 минут
pytest -m e2e --no-cov -q                   # браузер (Chromium) на настоящем сервере, около 5 минут
pytest tests/test_order_modes.py -x -q --no-cov   # один файл, быстрый цикл
```

Правила, из-за которых проект не ломался:

- **Один pytest за раз.** Тесты работают с общей тестовой базой, второй параллельный запуск её испортит. Chromium тоже один.
- **Память.** Полный прогон с Chromium и Postgres в Docker требует свободных 2 ГБ; при нехватке прогон зависает или его прерывает система (см. раздел 6).
- **Каждый этап закрывается полным набором:** lint, format, mypy, `alembic check`, `pytest --cov` (покрытие не ниже 97%), e2e. CI (`.github/workflows/ci.yml`) делает то же на Ubuntu с порогом покрытия 90%.
- **Скриншоты в `docs/screenshots/` перезаписывает e2e.** Перед коммитом отката верните лишние: `git checkout -- docs/screenshots` и удалите новые неотслеживаемые, обновляйте их осознанно.
- **Миграции проверяйте на отдельной базе:** `upgrade`, `downgrade -1`, снова `upgrade`, затем `alembic check`; тесты миграций на данных лежат в `tests/test_migration.py`.
- В коде нет комментариев и docstrings: смысл должен быть в именах и тестах; объяснения живут в `docs/`.

Нагрузка (k6 в Docker, внутри сети compose): сценарии `loadtest/peak.js` (пик начала пары) и `loadtest/lesson.js` (урок с жеребьёвкой, присутствием и оценками), SSE `loadtest/sse_peak.py`; команды и условия чистого замера в [LOADTEST.md](LOADTEST.md). Новые сценарии подготовлены, но ни разу не запускались: сначала освободите машину (закройте браузер и всё тяжёлое, остановите Ollama).

## 4. Структура проекта

```
main.py          приложение, обработчики ошибок, /health /ready /metrics, раздача страниц, фоновые задачи
routers/         HTTP: разбор запроса, зависимости, вызов сервиса (sessions, auth, live, protocol, budget, history, templates, spaces, analytics, ai, practice, qr)
services/        бизнес-логика (queue, protocol, budget, presence, retention, ordering, history, ...)
repositories/    запросы к БД (queue, protocol, history, spaces, user)
models/          ORM-модели SQLAlchemy;  schemas/  Pydantic-схемы запросов и ответов
core/            настройки (config.py), безопасность, лимиты, метрики, исключения, события
db/              движок и сессия
alembic/         env.py и versions/ (13 миграций)
static/          страницы: index (студент), teacher, protocol, students, spaces, practice
tests/           pytest; tests/e2e: браузерные сценарии и проверки ширины 360-375 px
deploy/          Caddyfile, backup.sh, restore.sh;  loadtest/  нагрузка;  docs/  документы
```

Слои: **router → service → repository → модель**. Router не ходит в БД, service не знает про HTTP (кроме типизированных исключений из `core/exceptions.py`, которые превращаются в ответ `{"detail": "...", "code": "...", "request_id": "..."}` с русским текстом и стабильным кодом). Изменения очереди сообщают подписчикам вызовом `notify_changed(code)` из `core/events.py`; SSE-хаб (`services/live.py`) перечитывает снимок очереди и рассылает.

### Миграции

Цепочка (от старой к новой): `a1b2c3d4e5f6` исходная схема, `b2c3d4e5f6a7` `sort_order`, `c3d4e5f6a7b8` группа, `d4e5f6a7b8c9` протокол, `e5f6a7b8c9d0` ИИ, `f6a7b8c9d0e1` «не готов» и окно записи, `a7b8c9d0e1f2` история студентов, `b8c9d0e1f2a3` шаблоны, `c9d0e1f2a3b4` группы, `d0e1f2a3b4c5` режимы порядка и журнал, `e1f2a3b4c5d6` бюджет времени, `f2a3b4c5d6e7` режимы сессии, `a3b4c5d6e7f8` присутствие. Каждая обязана иметь работающий `downgrade`. Откат удаляет данные добавленных столбцов и таблиц.

### Как добавить

**Эндпоинт.** 1) Схемы в `schemas/`. 2) Запросы в `repositories/`. 3) Логика в `services/`, ошибки через `ConflictError`, `NotFoundError` и другие с русским текстом и `code=`. 4) Маршрут в `routers/`, владельца проверять через `CurrentTeacher` и поиск по `teacher_id` (чужой объект даёт 404, а не 403). 5) Если нужен роутер, подключить в `main.py`. 6) Тесты: логика, права (чужой преподаватель, без токена), гонки там, где есть блокировки (`pg_advisory_xact_lock`, `FOR UPDATE`), строка в таблицу API в README. 7) Решение записать в `docs/DECISIONS.md`.

**Миграцию.** Изменить модель, написать файл в `alembic/versions/` с `down_revision` предыдущей головы, `upgrade` и `downgrade`, значения по умолчанию через `server_default`, чтобы старые строки остались валидными; прогнать `upgrade/downgrade/upgrade` и `alembic check`; добавить тест на данных в `tests/test_migration.py`; в `tests/conftest.py` базу создаёт `create_all`, а ревизию подставляет `expected_revision()`.

**Страницу.** Файл в `static/`, маршрут `FileResponse` в `main.py`, ссылка в шапках других страниц, токен преподавателя берётся из `sessionStorage` (`queue-teacher-token`), текст строить через `el()` и `textContent`, не через `innerHTML`. Правила вёрстки: класс `.hidden` должен перекрывать `display` (в `teacher.html` он с `!important`), на телефонах элементы не ниже 40 px, никакой горизонтальной прокрутки, широкие таблицы превращать в карточки. Добавить e2e-сценарий и проверку ширины в `tests/e2e/test_mobile_layout.py` или `test_phone_audit.py`. После правки скриптов запустить `node` для проверки синтаксиса: `new Function(текст скрипта)`; ошибка в одном `<script>` убивает всю страницу.

## 5. Как это устроено

**Очередь.** Запись проходит `waiting → called → done` (и `skipped`, `left`). Номер (`ticket`) выдаётся счётчиком сессии, порядок определяет `sort_order`: вызывают по `(not_ready, sort_order)`. «Вперёд» ставит `sort_order` ниже минимума, «вернуть» в конец. Все изменения очереди берут строку сессии `FOR UPDATE`; вход дополнительно проходит через `join_gate` (очередь входов в памяти) и вставку `INSERT ... SELECT ... WHERE` с проверкой лимитов. Студенту позицию даёт один SQL (`STUDENT_VIEW`), поток SSE отдаёт то же.

**Порядок (п. 33).** `join`: по номеру. `lottery`: пока запись открыта, студенты в пуле без номеров, `POST /lottery` под блокировкой закрывает запись, перемешивает через `random.SystemRandom`, номера «паркуются» (сдвиг констант) и расставляются заново, результат пишется в `session_events`; повтор идемпотентен. Готовность «сразу» сдвигает `sort_order` на `-READY_BAND` (`services/ordering.py`), поэтому запросы очереди не менялись; в режиме жеребьёвки готовые и остальные разыгрываются отдельно. Бонус хранится в `submissions.bonus_points` и не входит в баллы.

**Протокол.** Работа содержит критерии и банк вопросов; при вызове студента создаётся сдача и выбираются вопросы (`services/protocol_calls.py`: затравка, учёт уже показанных этому студенту, на пересдачу сначала невиданные). Завершение пишет баллы, итог, журнал `audit_log`, отмечает запись выполненной. Правки только с причиной и тоже в журнал. Критерии блокируются после первой сдачи.

**Быстрая оценка (п. 35).** Это обычная сдача по служебной работе (`assignments.is_system`) с одним критерием «Оценка»: история, аналитика и журнал не знают о режиме. Служебная работа скрыта в списках и защищена от правок.

**Присутствие (п. 37).** Код `HMAC-SHA256(JWT_SECRET_KEY, "presence:<id сессии>:<окно>") mod 10^6`, окно `floor(время / интервал)`, принимаются текущее и предыдущее; перебор считает `AttemptGuard` в памяти (адрес и сессия, блокировка 429).

**Бюджет времени (п. 34).** Чистая функция `forecast` (`services/budget.py`): остаток, запас 10%, бюджет на студента, прогноз по `avg_service_seconds`; предложение уменьшить вопросы только при статусе «не успеваем», решение хранится в `questions_override` и журнале.

**Очистка данных (п. 38).** `services/retention.py`: фоновая задача раз в час и команда `python -m services.retention --days N [--apply]`; удаляются закрытые сессии старше срока и осиротевшие записи студентов, журналы не трогаются. По умолчанию 180 дней (`DATA_RETENTION_DAYS`, `0` отключает).

**Безопасность и лимиты.** Лимиты по IP и по токену в `core/ratelimit.py`, общий лимит одновременных запросов в `core/limits.py`, пул БД 30 соединений (10 в боевом файле), `/metrics` под токеном.

## 6. Типовые проблемы

| Симптом | Что делать |
|---|---|
| Контейнер `web` не поднимается | `docker compose logs web`: пустые или заглушечные секреты, JWT-ключ короче 32 символов, код приглашения короче 8, неверный `DATABASE_URL`. `/ready` отвечает `schema_outdated`: не применены миграции, `docker compose exec web alembic upgrade head` |
| После перезапуска Docker порт 5434 не опубликован (в `docker ps` только `5432/tcp`) | Контейнер БД пересоздаётся с портом из `docker-compose.yml`, данные в томе не пропадают: `docker compose up -d --force-recreate postgres`. Перед этим сделайте копию: `docker exec queue_db pg_dump -U postgres -Fc queue_db > копия.dump` |
| Тесты падают с `ConnectionRefused` | Не запущен Docker или БД; проверьте `DATABASE_URL`, порт и `pg_isready` |
| Тесты зависают или падают из-за нехватки памяти | Закройте тяжёлые программы, перезапустите Docker Desktop, проверьте свободную память (нужно около 2 ГБ), запускайте файлами. Для поиска зависшего теста поставьте `pytest-timeout` и запустите `pytest -v --timeout=240 > лог` |
| Нестабильный `test_live.py::test_burst_of_changes_is_coalesced_into_few_database_reads` | Считает обновления за короткое время, зависит от скорости машины; в одиночку проходит. Перезапустите отдельно; на постоянное падение в одиночном запуске обратите внимание всерьёз |
| e2e: на Linux падает проверка ширины, на Windows нет | Шрифты разные. Проверка `assert_fits` в `tests/e2e/test_mobile_layout.py` называет вылезающий элемент |
| Страница студента или преподавателя «мёртвая» | Синтаксическая ошибка в скрипте страницы (например, повторное объявление `const`); проверьте скрипт через `node` |
| `curl` с кириллицей в теле на Windows даёт ошибку разбора | Используйте файл с телом или имена без кириллицы |
| Предупреждения о CRLF при `git add` | Безвредны; в репозитории окончания строк LF |

## 9. Ограничения и идеи на будущее

Подробности в [KNOWN_ISSUES.md](KNOWN_ISSUES.md). Главное: один процесс (для нескольких нужен Redis или `LISTEN/NOTIFY` для SSE, лимитов и счётчиков присутствия); новые функции не прогонялись под нагрузкой; проверка присутствия не защищает от пересылки кода; проверено только в Chromium (Safari, Firefox и настоящие телефоны не проверялись); очистка данных необратима и не трогает журналы; оценка вопроса в слабых местах косвенная.

Идеи: Redis для общего состояния и нескольких реплик; хранение версий работ вместо снимков; настоящее приглашение студентов списком и вход через учётную запись колледжа; пометки и наборы критериев, настраиваемые преподавателем; мониторинг и оповещения; внешнее хранение резервных копий; автоматическое восстановление в проверочную базу по расписанию; проверка в Safari и Firefox на настоящих устройствах.
